# Create Dashboard Skill

Creates and updates the `Dashboard.md` file in the Obsidian vault — the real-time command center for the AI Employee.

## What This Skill Does

Generates or updates `AI_Employee_Vault/Dashboard.md` with a live summary of the entire system: pending tasks, recent activity, system health, and key metrics.

## Dashboard.md Template

```markdown
---
last_updated: {{CURRENT_ISO_TIMESTAMP}}
auto_generated: true
---

# AI Employee Dashboard

## System Status
| Component       | Status  | Last Check           |
|-----------------|---------|----------------------|
| Gmail Watcher   | offline | —                    |
| File Watcher    | offline | —                    |
| Orchestrator    | offline | —                    |

## Pending Actions
<!-- Auto-populated from /Needs_Action/ -->
_No pending actions._

## Awaiting Approval
<!-- Auto-populated from /Pending_Approval/ -->
_No items awaiting approval._

## Recent Activity
<!-- Auto-populated from /Done/ (last 10 items) -->
_No recent activity._

## Quick Stats
- **Tasks Completed Today**: 0
- **Tasks Pending**: 0
- **Approvals Waiting**: 0
- **Errors (24h)**: 0

---
*Auto-generated by AI Employee*
```

## Step-by-Step Process

1. Check if `AI_Employee_Vault/Dashboard.md` exists
2. If creating new: write the full template with current timestamp
3. If updating: scan these folders and update counts:
   - `/Needs_Action/` → count files → update "Pending Actions" section
   - `/Pending_Approval/` → count files → update "Awaiting Approval" section
   - `/Done/` → list last 10 items → update "Recent Activity" section
   - `/Logs/` → count today's errors → update error count
4. Update `last_updated` timestamp in frontmatter
5. Preserve any manually added sections by the user

## Important Rules

- Always update `last_updated` timestamp when modifying
- List items in reverse chronological order (newest first)
- Never delete user-added custom sections
- Keep the file under 200 lines for Obsidian readability
- Use relative links for cross-vault references

## When to Use

- After vault-setup to create initial Dashboard.md
- Periodically to refresh status counts
- After any task is completed or moved between folders
- When user asks for current system status
